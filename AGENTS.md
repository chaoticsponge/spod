# Project instructions

- Keep README.md limited to a brief compatibility description, one-line feature bullets, and one installation sentence linking to `dist/spod.jar?raw=true`.
- Do not add build instructions, validation results, in-game checklists, development history, or changelogs to the README.
- When releasing a new mod build, refresh `dist/spod.jar` from the successfully built versioned JAR so the GitHub README download stays current.
- The canonical repository is https://github.com/chaoticsponge/spod; publish future spod updates there.
- Publish separate GitHub releases for builds targeting different Minecraft or Cobblemon versions; keep previous releases and artifacts available rather than replacing them with incompatible builds.
- Include the mod version, Minecraft version, loader, and targeted Cobblemon profile version (when applicable) in release titles and notes; distinguish compatibility targets from versions actually tested in-game.
- Use version-specific release tags, such as `v1.12.0-mc1.21.1-cobblemon1.8.2`, and attach the matching built JAR to each release.
